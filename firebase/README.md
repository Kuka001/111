# Облако AGY Roleplay: настройка Firebase

Облако хранит зашифрованную копию ваших данных в **вашем собственном** проекте Firebase. Туда попадают персонажи, персоны, чаты с мыслями и вариантами, память чатов, системный промпт и настройки. Копия привязана к вашему аккаунту Google.

- **Бесплатно:** тариф Spark, банковская карта не нужна.
- **Время:** 15–20 минут, один раз.
- **Нужно:** аккаунт Google и браузер. Удобнее на компьютере; на телефоне тоже можно.

Без облака приложение работает как раньше, только на этом телефоне.

## Как это устроено

- **Рабочая копия остаётся на телефоне.** Поэтому приложение быстрое и работает без интернета. Изменения уходят в облако через несколько секунд. Изменения с других устройств приходят при открытии приложения или по кнопке «Синхронизировать».
- **Сквозное шифрование.** Каждая запись шифруется прямо на телефоне (AES-256-GCM) ключом данных. Сам ключ в облаке лежит только в зашифрованном виде: его закрывают ваш **пароль шифрования** (PBKDF2-SHA256, 600 000 итераций) и **код восстановления**.
- **Кто видит данные.** Ни Google, ни Firebase, ни разработчик не могут прочитать данные. Им видно только:
  - сколько у вас записей;
  - какого они размера;
  - когда записывались;
  - ваш email.
- **Кто может войти.** Правила Firestore пускают только ваш аккаунт Google и только к вашим записям.
- **Ключи на телефоне.** Ключ данных и токен входа хранятся зашифрованными ключом Android Keystore. Они не попадают:
  - в интерфейс;
  - в резервные копии;
  - в журналы.

## Шаг 1. Создайте проект Firebase

1. Откройте <https://console.firebase.google.com> и войдите тем аккаунтом Google, к которому хотите привязать данные.
2. Нажмите **«Create a project»** («Создать проект»). Имя любое, например `agy-roleplay-cloud`.
3. Google Analytics не нужен — выключите его. Нажмите **Create project**.
4. Тариф по умолчанию — **Spark (бесплатный)**. Не переходите на Blaze.

## Шаг 2. Включите вход через Google

1. В меню слева: **Build → Authentication → Get started**.
2. Вкладка **Sign-in method** → **Google** → включите **Enable**.
3. Укажите свой email в поле «Support email» и нажмите **Save**.

Другие способы входа включать не нужно.

## Шаг 3. Создайте базу Firestore и опубликуйте правила

1. **Build → Firestore Database → Create database.**
2. Выберите:
   - **Edition:** Standard (бесплатная квота есть только у неё);
   - **Database ID:** оставьте `(default)`: бесплатная квота действует только для этой базы;
   - **Location:** ближайший к вам регион, например `europe-west3` или `eur3`. Изменить регион потом нельзя;
   - **Start in production mode.**
3. Нажмите **Create**.
4. Откройте вкладку **Rules**. Удалите всё, что там есть, и вставьте содержимое файла [`firestore.rules`](firestore.rules) из этой папки.
5. Замените `OWNER_EMAIL` на свой Gmail — тот, которым будете входить в приложении. Например: `request.auth.token.email == 'you@gmail.com'`.
6. Нажмите **Publish**.

## Шаг 4. Возьмите `apiKey` и `projectId`

1. На главной странице проекта (**Project Overview**) нажмите **«+ Add app»** → значок **Web** (`</>`).
2. Имя любое, например `agy`. Firebase Hosting **не** включайте. Нажмите **Register app**.
3. Появится фрагмент кода `const firebaseConfig = { … }`. Из него нужны `apiKey` и `projectId`. Скопируйте фрагмент целиком — приложение само найдёт нужные значения.

Найти его позже: ⚙ **Project settings → General → Your apps → SDK setup and configuration → Config**.

## Шаг 5. Создайте OAuth-клиент «Desktop app»

Это делается в Google Cloud Console — у вашего проекта Firebase там тот же проект.

1. Откройте <https://console.cloud.google.com>. Вверху выберите проект с тем же именем, что в Firebase.
2. Меню ☰ → **Google Auth Platform**. Он же «APIs & Services → OAuth consent screen».
3. Если появится **Get started**, заполните:
   - **App name:** `AGY Roleplay`;
   - **User support email:** ваш email;
   - **Audience:** External;
   - контактный email;
   - согласие с условиями → **Create**.
4. Раздел **Audience**:
   - статус **Testing** (оставьте);
   - в **Test users** нажмите **Add users** и добавьте свой Gmail → **Save**.

   В режиме Testing войти могут только перечисленные тестовые пользователи. Это ещё один замок, кроме правил Firestore.
5. Раздел **Clients** → **Create client**:
   - **Application type: Desktop app** — обязательно этот тип;
   - имя любое, например `AGY Roleplay Android`;
   - **Create**.
6. Скопируйте **Client ID** и **Client secret** или нажмите **Download JSON**.

Для приложений типа Desktop Google не считает Client secret секретом. Но не публикуйте его — вместе с остальными значениями.

## Шаг 6. Разрешите этот клиент в Firebase

1. Вернитесь в консоль Firebase: **Authentication → Sign-in method → Google**.
2. Раскройте **«Safelist client IDs from external projects»**.
3. Нажмите **Add**, вставьте **Client ID** из шага 5 и нажмите **Save**.

Без этого Firebase может ответить «не принял вход Google».

## Шаг 7. Подключите приложение

1. Перенесите на телефон четыре значения: `projectId`, `apiKey`, `clientId`, `clientSecret`. Например, отправьте их себе в «Избранное» мессенджера или в Google Keep.

   Можно в любом виде:
   - JSON:
     ```json
     {
       "projectId": "agy-roleplay-cloud",
       "apiKey": "AIza…",
       "clientId": "1234567890-abc….apps.googleusercontent.com",
       "clientSecret": "GOCSPX-…"
     }
     ```
   - или подряд фрагмент `firebaseConfig` из шага 4 и JSON клиента из шага 5 — приложение само найдёт нужные значения.
2. В приложении: **Настройки → Облако и аккаунт**. Вставьте значения и нажмите **Сохранить**.
3. Нажмите **Войти через Google** и выберите свой аккаунт.

   Если появится предупреждение, что Google не проверил приложение, — это ваше собственное приложение: нажмите «Продолжить».
4. На странице **«Почти готово»** нажмите **«Вернуться в приложение»** или просто переключитесь на него. Вход завершится в приложении: в фоне Android 15+ не даёт ему выходить в интернет.

   Если браузер не вернул вас в приложение: скопируйте адрес из строки браузера (`http://127.0.0.1:…`) и вставьте его в поле «Браузер не вернул в приложение?».
5. Придумайте **пароль шифрования**. Лучше фраза из 4–5 слов. Его будут спрашивать только на новом телефоне.
6. Сохраните **код восстановления** — в менеджере паролей или на бумаге, отдельно от пароля. Он показывается один раз.

После этого всё, что есть на телефоне, зашифруется и загрузится в облако.

## Необязательно: ограничьте ключ API этим приложением

Google Cloud Console → **APIs & Services → Credentials** → ваш ключ (обычно «Browser key (auto created by Firebase)»):

- **Application restrictions → Android apps → Add:**
  - пакет `com.agy.roleplay`;
  - отпечаток SHA-1 — он показан в приложении: «Облако и аккаунт» → «Ограничить ключ API этим приложением».
- **API restrictions → Restrict key:** отметьте **Identity Toolkit API** и **Token Service API**.

## Новый телефон или переустановка

1. Установите приложение.
2. «Облако и аккаунт» → вставьте конфигурацию.
3. Войдите тем же аккаунтом Google.
4. Введите пароль шифрования — данные загрузятся.

Если на новом телефоне уже были данные, приложение спросит, что с ними сделать:

- **«Объединить»** — данные телефона и облака сольются.
- **«Заменить данными из облака»** — данные на телефоне будут стёрты.

## Если забыли пароль

1. На экране ввода пароля нажмите **«Забыли пароль? Ввести код восстановления»**.
2. После входа задайте новый пароль: **«Сменить пароль»** → «Не помню — ввести код восстановления».

Если потеряны **и пароль, и код**, данные в облаке не расшифровать никому. Но если на каком-то телефоне облако ещё открыто:

1. Нажмите **«Удалить данные из облака»**.
2. Войдите снова и создайте хранилище с новым паролем — данные с этого телефона загрузятся заново.

## Если потерян телефон

Данные на самом телефоне защищены его блокировкой экрана и шифрованием Android. Чтобы отключить потерянный телефон от облака:

1. На новом телефоне войдите и откройте облако паролем. Дождитесь окончания загрузки.
2. **«Удалить данные из облака»**, включив **«Удалить и аккаунт в Firebase»**. Это обрывает вход на всех устройствах, включая потерянное.
3. Снова **«Войти через Google»** и создайте хранилище с **новым** паролем — всё загрузится заново.

## Бесплатные лимиты (тариф Spark)

| Что | Лимит |
|---|---|
| Данные | 1 ГиБ |
| Чтения | 50 000 в сутки |
| Записи | 20 000 в сутки |
| Удаления | 20 000 в сутки |

- Сутки сбрасываются в полночь по тихоокеанскому времени (США).
- Одна запись в облаке — одно сообщение, один чат или одна карточка.
- Первая загрузка тратит по записи на каждую из них. Дальше — несколько записей на каждое ваше действие.
- Расход за сегодня виден в «Облако и аккаунт».
- Если лимит исчерпан, синхронизация продолжится на следующие сутки. Данные на телефоне в порядке.

## Ошибки

| Сообщение в приложении | Что сделать |
|---|---|
| «Firestore отказал в доступе…» | Шаг 3: правила опубликованы, `OWNER_EMAIL` заменён на ваш Gmail ровно так, как вы входите |
| «В Firebase не включён вход через Google» | Шаг 2 |
| «Firebase не принял вход Google…» | Шаг 6: добавьте Client ID в Safelist |
| «Вход отменён… тестовые пользователи» | Шаг 5.4: добавьте свой Gmail в Test users |
| «OAuth-клиент должен быть типа «Desktop app»» | Шаг 5.5: создайте клиент типа Desktop app и вставьте его Client ID и secret |
| «неверный Client ID или Client secret» | Скопируйте их заново (шаг 5) |
| «Неверный apiKey…» | Скопируйте `apiKey` заново (шаг 4) |
| «API-ключ ограничен…» / «API-ключу запрещён этот сервис» | Проверьте ограничения ключа (раздел «Необязательно») |
| «Не найдено. Создана ли база Firestore (default)?» | Шаг 3: база должна называться `(default)` |
| «Исчерпан бесплатный суточный лимит» | Ничего: синхронизация продолжится сама |
